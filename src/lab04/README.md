# ЛР4 — Файлы: TXT/CSV и отчёты по текстовой статистике

## Задание A - модуль src/lab04/io_txt_csv.py

Реализован независимый модуль ввода/вывода (src/lab04/io_txt_csv.py), содержащий чистые функции с аннотациями типов:

read_text: открывает и считывает текстовый файл целиком в одну строку в заданной кодировке (по умолчанию UTF-8). В докстринге описана возможность явной смены кодировки (например, encoding="cp1251").

write_csv: принимает итерируемый объект со строками, валидирует их (в текущей реализации преобразует в список через list(), чтобы избежать проблем с генераторами) и записывает данные в CSV-файл с разделителем ,. Используется newline="" для корректной работы на Windows.

ensure_parent_dir (логика внутри write_csv): проверяет существование целевой директории для файла и автоматически создает её, если она отсутствует (p.parent.mkdir(parents=True, exist_ok=True)).

Обработанные краевые случаи:

Пустой входной файл корректно считывается как пустая строка "". Программа не падает, а создает CSV только с заголовком.

Вызов write_csv без данных и без заголовка создает пустой файл размером 0 байт. Если передан только header, записывается файл, состоящий из одной строки заголовка.

## Задание B - скрипт src/lab04/text_report.py

Скрипт src/lab04/text_report.py корректно обрабатывает случай, когда на вход подается абсолютно пустой файл (0 байт) или файл, состоящий только из пробелов.

Логика: В функции get_freq стоит проверка if text.strip(). Если после удаления пробелов строка пустая, возвращается пустой словарь {}. Функция sort_freq сортирует пустой словарь, получая пустой список.

Результат: Функция write_csv получает пустой список строк, но так как передан header=("word", "count"), в файл report.csv записывается только заголовок.

Вывод в консоль: Выводятся нули (Всего слов: 0, Уникальных слов: 0), раздел Топ-5 остается пустым (благодаря защите top_n(...) or []).

## Задание C - кодировка cp1251

Реализована поддержка чтения файлов в нестандартных кодировках.

Логика: В CLI добавлен аргумент --encoding (по умолчанию "utf-8"). Он передается в функцию read_text. Если файл сохранен в Windows-1251, достаточно указать --encoding cp1251.

Обработка ошибок: В главном скрипте блок try/except перехватывает FileNotFoundError и UnicodeDecodeError. Если кодировка не подошла или файла нет, скрипт печатает понятное сообщение в stderr и выходит с кодом 1.

Запись: Независимо от входной кодировки, выходной CSV-файл всегда сохраняется в utf-8 (жестко задано в write_csv), чтобы избежать проблем с отображением в современных редакторах.

## Задание D★ - несколько файлов (пер‑файл и сводный)

Скрипт поддерживает обработку нескольких входных файлов одновременно и создание двух видов отчетов.

Логика: Аргумент --in принимает nargs="+" (список файлов). Скрипт проходит циклом по всем файлам, считает частоты для каждого и накапливает их в глобальном счетчике Counter (g_freq.update(f_freq)).

Пофайловый отчёт (--per-file): Данные складываются в список кортежей (имя_файла, слово, частота). Сортировка выполняется по ключу (x[0], -x[2], x[1]), что соответствует требованию: file ↑, count ↓, word ↑. Заголовок CSV: file,word,count.

Сводный отчёт (--total): Использует функцию sort_freq (сортировка по count ↓, затем word ↑). Заголовок CSV: word,count.

## Табличный вывод: 

Реализована функция print_table, которая динамически форматирует вывод в консоль, подстраиваясь под длину слов (как в ЛР3★).

Логика: Функция принимает список заголовков и список строк. Сначала все данные приводятся к строкам. Затем для каждого столбца вычисляется максимальная ширина (берется максимум из длины заголовка и длины самого длинного слова в столбце).

Форматирование: С помощью метода ljust() добавляются пробелы справа, чтобы выровнять столбцы. Разделители | и + формируют сетку.

Вызов: Таблицы автоматически печатаются в консоль, если пользователь указал флаги --per-file или --total. Это позволяет визуально проверить данные, не открывая CSV-файлы.
